# Portable AI USB

Portable AI USB — локальное Windows/macOS приложение для хранения файлов в зашифрованном контейнере, поиска по ним и ответов небольшой локальной модели. Рабочий каталог проекта: `LLMLIB`. Версия исходников: `0.2.0`.

## Запуск и содержимое флешки

На носитель копируются приложение для нужной ОС и затем создаваемые при первом запуске `disk.data` и `data.cache`. На macOS приложение переносится как `PortableAI.app`; внутри него лежат исполняемый файл и автономный runtime. На Windows это `PortableAI.exe`. Python и сеть для основного режима не нужны.

При первом запуске выберите пустой каталог флешки и задайте мастер-пароль минимум из 12 символов. Программа не удаляет обнаруженные файлы. Пароль требуется при каждом запуске и повторно перед изменением файлов, моделей, настроек CPU и сбросом. Пароль не сохраняется; потерянный пароль восстановить нельзя.

Нажмите **Обновить модели**, выберите тип модели, затем локальный файл GGUF. Повторите для второй модели. Модели вручную копируются из предварительно скачанных файлов и шифруются внутри `disk.data`; их не требуется оставлять отдельными файлами на флешке. Для проверки совместимости в разработке использовалась связка Qwen2.5-0.5B-Instruct Q4_K_M и multilingual-e5-small F16. Другие GGUF могут использовать несовместимый формат диалога или способ подготовки embeddings.

Доступны добавление и удаление файлов, инкрементальная или полная переиндексация, локальный чат с историей, стартовая сводка, список найденных источников, отдельные окна просмотра и подсветка слов вопроса. Субтитры `.srt`/`.vtt` с именем, совпадающим с видео, открывают найденный фрагмент на его временной отметке. Настройка CPU задаёт число рабочих потоков модели (1–4). Полный сброс удаляет только два контейнера приложения и просит подтвердить действие.

## Хранилище и приватность

- `disk.data` — SQLite-контейнер с AES-GCM шифрованием блоков; в нём лежат исходные файлы, модели, индекс и эмбеддинги. Используется ключ, производный от мастер-пароля через scrypt.
- `data.cache` — отдельный AES-GCM контейнер с историей вопросов/ответов, короткими снимками найденного контекста и настройками. Эти данные помогают модели учитывать уточняющие вопросы. Цепочки скрытых рассуждений не сохраняются: приложение их не получает, а продолжение диалога использует историю и источники.
- Имена объектов, содержимое, история и индекс зашифрованы. Техническая структура SQLite, версия формата, соль, число объектов и размеры блоков остаются видимыми.
- Перед запуском llama.cpp временно расшифровывает GGUF-модель в каталоге ОС. Она обычно удаляется при завершении операции, но принудительное завершение, авария ОС, файл подкачки или резервные копии ОС могут оставить данные на компьютере. Для файлов модели также нужен свободный объём на временном диске.
- Переносите носитель между компьютерами после закрытия приложения. Если контейнер был изменён другим экземпляром, устаревший экземпляр откажется перезаписывать индекс.

## Поддерживаемые материалы

Текст и код: `.txt`, Markdown, reStructuredText, CSV/TSV, JSON/JSONL, XML, YAML, TOML, конфигурационные файлы, логи, Jupyter Notebook, HTML и исходники Python, JavaScript/TypeScript, Java/Kotlin, C/C++, C#, Go, Rust, Swift, SQL, Shell, PowerShell, Ruby, PHP, Lua, R, Julia, Dart, Haskell, Elixir, Erlang, Clojure, Terraform и близкие текстовые форматы. Извлекаются текстовые слои PDF, DOCX, XLSX и PPTX; также EPUB, ODT, ODS, ODP и RTF. Для архивов поддерживаются ZIP, TAR, TGZ, GZIP, BZIP2, XZ/LZMA и 7z. Архивы не распаковываются на носитель.

Изображения показываются в отдельном окне. Аудио и видео проигрываются встроенным плеером, если формат поддерживает медиакодек текущей ОС; текстовая транскрибация не выполняется. Для видео таймкоды берутся из одноимённых SRT/VTT-субтитров. OCR для изображений и сканированных PDF не реализован. RAR и зашифрованные архивы не индексируются. При неподдерживаемом или повреждённом файле в журнале индексации указывается причина.

Пределы бета-версии: файл для анализа текста — 10 МБ; один элемент архива — 5 МБ; суммарное чтение архива — 20 МБ, глубина вложенных архивов — 2 уровня; PDF — до 500 страниц; предпросмотр медиа — до 100 МБ; индекс ограничивает извлечённый текст до 2 млн символов на документ. Большие исходные файлы можно хранить зашифрованными, но они могут быть пропущены при индексации или просмотре. Ограничения уменьшают нагрузку и риск архивных бомб, но парсеры не изолированы в отдельной песочнице.

## Автообновление

Собранное приложение проверяет подписанный манифест GitHub Releases при запуске. Проверка подписи Ed25519, размера пакета и SHA-256 выполняется до установки; обновляется только само приложение, `disk.data` и `data.cache` остаются на месте. При недоступной сети программа продолжает работать офлайн. Изменение моделей и файлов через интернет не выполняется.

`.github/workflows/build.yml` собирает Windows x64, macOS Apple Silicon и macOS Intel на соответствующих GitHub runners. Ручной запуск workflow публикует тестовые артефакты. При push тега `vX.Y.Z` выполняется выпуск GitHub Release с `portableai-update.json`, подписанным Ed25519. Для этого в настройках репозитория GitHub Actions должен быть задан секрет `PORTABLEAI_UPDATE_KEY_PEM` со значением PEM-закрытого ключа, соответствующего `update-public-key.hex`. Ключ нельзя добавлять в git или артефакт.

Сборка macOS в этом репозитории не подписывается сертификатом Developer ID и не нотариализируется; GitHub может помечать скачанный пакет как неподписанный. Для бесшовной установки на macOS к workflow нужно добавить Developer ID и нотарификацию с учётными данными владельца. Windows EXE в текущем workflow также не имеет Authenticode-подписи. Подпись манифеста подтверждает целостность пакета для автообновления, но не является подписью ОС.

## Сборка разработчиком

Требуется Python 3.12+, CMake, C++ toolchain и llama.cpp. Для настоящей macOS `.app` и Windows `.exe` сборка выполняется отдельно на каждой ОС: PyInstaller не является кросс-компилятором. Workflow использует CPU-сборку llama.cpp b10488, зафиксированную на commit `9d77fa17254e1dee4b9e92504c91611a60b1359f`, и отключает веб-интерфейс движка.

Установите зависимости из `requirements.txt`, соберите llama-server в CPU-режиме по параметрам `.github/workflows/build.yml`, затем выполните:

```sh
python package.py PATH_TO_LLAMA_SERVER
```

Результат появляется в `dist/`. Проверка исходников и локальный запуск без упаковки:

```sh
python -m unittest discover -s tests -v
python app.py PATH_TO_EMPTY_TEST_DIRECTORY
```

Для безэкранного тестового окружения установите `QT_QPA_PLATFORM=offscreen`.

## Границы готовности

Исходники включают основной поток приложения, шифрованное хранилище, две локальные модели, RAG, просмотр, архивные ограничения, фоновые операции и механизм обновления. Это тестовая сборка без стороннего аудита криптографии и без подтверждённой эксплуатации на всех версиях Windows/macOS. Настоящие Windows и Intel Mac артефакты создаются GitHub Actions; локально доступна сборка macOS arm64. Полный сброс не выполняет гарантированное физическое стирание ячеек флеш-памяти.
